## 1. 背景与目标

用户长期停留在右下角最小化小窗时，若要改专注时长、休息时长、自动发起下一次专注、工资等配置，目前只能先点「还原」回到主窗，再点「设置」。路径偏长。

**目标**：在最小化小窗上增加「设置」入口，让用户不必离开小窗模式也能打开设置。

**成功标准**：小窗可见设置按钮；点击后能完整查看/修改/保存现有设置项；保存后小窗状态与配置同步；不破坏现有「记录 / 还原」行为。

## 2. 代码现状

### 2.1 小窗现有控件（mini.html）

| 区域 | 控件 |
|------|------|
| 操作区 | 开始 / 暂停 / 停止 |
| 页脚 | 📋 记录、还原 |
| 层级 | 最上层 / 最下层 |
| 其它 | 最小化到后台、退出程序 |

**没有设置按钮。**

### 2.2 设置能力在哪

- 设置 UI 在主窗 index.html 的 #config-modal
- 打开逻辑在 main.js 的 openConfigModal()（填充表单并显示弹窗）
- 配置读写走现有 get-config / save-config；保存后主进程已会向小窗广播 config-loaded

### 2.3 可复用先例：「记录」

小窗点「记录」的现有链路：

```text
mini-renderer → IPC open-record-from-mini
  → 主进程：mainWindow.show() + focus
  → 主进程：webContents.send('show-record-modal')
  → 主窗：打开记录弹窗
  → 小窗保持存在（不走 restore）
```

这是「从小窗打开主窗能力、又不退出最小化模式」的既有模式，设置入口应对齐它。

## 3. 推荐方案（A）

### 3.1 交互

1. 小窗页脚「记录 / 还原」同一行增加 **「⚙️ 设置」**（或文案「设置」，风格与「📋 记录」一致）。
2. 点击后：
   - 显示并聚焦主窗口；
   - 打开主窗已有设置弹窗；
   - **不销毁小窗**（与「记录」一致，不同于「还原」）。
3. 用户在主窗保存或关闭设置后：
   - 小窗继续显示；
   - 若已保存，依赖现有 config-loaded 同步专注时长等（无需新同步通道）。
4. 用户若不想看主窗，可再次点主窗最小化，或继续用小窗操作；本次不强制自动藏主窗。

### 3.2 布局建议

```text
[📋 记录]  [⚙️ 设置]  [还原]
```

- 按钮样式复用 .restore-btn / .mini-btn-record
- 区域保持 -webkit-app-region: no-drag
- 小窗宽度约 250px，三按钮一行略紧；若换行或略增宽（如 260–270），可接受，优先保证可点、不挤成一团
- **不**在小窗内嵌完整设置表单（空间不够，也避免双份设置 UI）

### 3.3 技术改动（最小面）

| 层级 | 改动 |
|------|------|
| mini.html | 增加设置按钮 |
| mini-renderer.js | click → ipcRenderer.send('open-settings-from-mini') |
| main.js（主进程） | 新增 ipcMain.on('open-settings-from-mini')：show/focus 主窗 + send('show-config-modal')，逻辑镜像 open-record-from-mini |
| main.js（渲染） | 监听 show-config-modal → 调用已有 openConfigModal() |

**不改**：设置表单字段、保存校验、autoStartNextFocus 等业务配置本身。

### 3.4 时序

```text
用户点击小窗「设置」
  → open-settings-from-mini
  → mainWindow.show() + focus()
  → show-config-modal
  → openConfigModal()
  → 用户编辑并保存 / 取消
  → 保存时走现有 save-config → 小窗收到 config-loaded（已有）
```

## 4. 方案对比

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A. 镜像「记录」（推荐）** | 显示主窗 + 打开设置弹窗，小窗保留 | 改动小、与现有交互一致、复用完整设置 UI | 会短暂露出主窗 |
| B. 点设置等于「还原」再开设置 | 销毁小窗，主窗开设置 | 实现也简单 | 用户只想改一项配置却被迫退出最小化 |
| C. 小窗内嵌精简设置 | 在 mini 里做时长等表单 | 不露主窗 | 双份 UI、空间挤、维护成本高 |

**推荐 A。**

## 5. 验收标准

| 场景 | 期望 |
|------|------|
| 小窗可见 | 有设置按钮，与记录/还原同区、可点 |
| 点击设置 | 主窗出现并打开设置弹窗；小窗仍在 |
| 修改并保存 | 配置落库；小窗专注时长等随 config-loaded 更新 |
| 取消/关闭设置 | 配置不变；小窗仍可用 |
| 与记录并存 | 「记录」「设置」互不干扰；各自打开对应弹窗 |
| 还原仍可用 | 「还原」仍销毁小窗并只显示主窗，行为不变 |
