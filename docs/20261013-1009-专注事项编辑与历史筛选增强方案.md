# TimeEnd 专注事项编辑与历史筛选增强方案

## 1. 背景与目标

当前「专注事项」仅在专注结束时的打断弹窗中填写，字段为 `inputContent`（纯文本）。专注过程中无法查看或编辑事项；历史记录只读，无法修改；按天筛选已有原生日期选择器，但不支持直接输入日期。

本方案目标：

1. **专注中**：主界面右侧增加入口，可弹出查看/编辑当前专注事项
2. **专注结束**：结束流程直接沿用（或预填）已编辑好的事项内容
3. **历史记录**：已保存的专注事项可再次编辑、修改并保存
4. **日期筛选**：支持手动输入日期 + 时间组件选择，二者联动

> 本文档仅供审核，确认后再进入实现。

| # | 用户诉求 | 方案理解 |
|---|----------|----------|
| A | 专注中右边加按钮，弹出编辑/显示当前事项 | 专注进行中显示入口；弹层内展示并编辑草稿 |

2. 「右边」指计时区域右侧或控制区右侧的固定入口（非独立侧栏）
3. 休息记录不涉及事项编辑
4. 周/月筛选本期保持快捷按钮，日期输入增强优先覆盖「按天」

## 4. 功能方案

### 4.1 专注中：事项入口与弹层

**入口**

- 位置：主界面计时/状态区域**右侧**（或紧邻时间显示的右上角），按钮文案建议「事项」或图标 +「事项」
- 可见性：仅在**专注进行中**（含暂停）显示；准备就绪/休息中隐藏
- Mini 窗口：本期可选——若空间紧，可仅主窗口提供；若需要可后续加同一入口

**弹层内容**

- 标题：当前专注事项
- 多行文本框：绑定进行中草稿
- 操作：保存 / 关闭
  - **保存**：写入内存草稿（及可选本地临时持久化），不结束专注
  - **关闭**：若有未保存改动，二次确认或自动保存（推荐：**失焦/关闭时自动保存草稿**，减少打断）

**交互示意**

```
┌─────────────────────────────────┐
│  TimeEnd              [事项] ←─┤  专注中右侧按钮
│         24:30                   │
│       专注中…                   │
└─────────────────────────────────┘
              ↓ 点击
┌─────────────────────────────────┐
│ 当前专注事项              ×    │
│ ┌─────────────────────────────┐ │
│ │ （可编辑文本）              │ │
│ └─────────────────────────────┘ │
│              [保存]             │
└─────────────────────────────────┘
```

### 4.2 专注结束：使用已编辑事项

**数据流**

1. 开始专注 → 清空 `currentFocusMatter`（草稿）
2. 专注中编辑 → 更新草稿
3. 自然结束 / 手动停止 → 打开打断窗时**预填草稿**
4. 用户可在打断窗继续修改；提交时以打断窗最终文本为准
5. 若打断窗为空且存在草稿 → 使用草稿（兜底）
6. 保存后清空草稿

**手动停止「跳过」**

- 若草稿非空：建议仍写入草稿内容（符合「直接使用编辑好的事项」）
- 若草稿为空：保持现行为空字符串

**自动开始下一次专注**

- 新一轮开始时清空草稿，避免带入上一轮事项

### 4.3 历史记录：编辑与保存

**列表 UI**

- 每条专注记录增加「编辑」按钮
- 点击进入行内编辑或小弹层：多行输入，展示原 `inputContent`
- 「保存」写回；「取消」恢复展示

**存储**

- 新增 `sessionStore.updateFocusSession(id, { inputContent })`
- 按 `id` 定位所在周文件 → 修改对应 focus 记录 → 写回
- 本期**不修改** `startTime` / `endTime` / `durationMinutes`（仅改事项文案）
- 可选增加 `updatedAt` 便于排查（非必须）

**校验**

- 允许保存为空（清空事项）
- 找不到 `id` 时提示失败并不静默丢弃

### 4.4 日期筛选增强（按天）

在现有「今天 / 昨天 / `<input type="date">`」基础上：

| 控件 | 行为 |
|------|------|
| 文本输入框 | 可输入 `YYYY-MM-DD`；失焦或回车后解析并刷新列表 |
| 日期选择器 | 现有 `type="date"`；变更时同步到文本框并刷新 |
| 今天/昨天 | 同步文本框与选择器 |

**非法输入**：提示格式错误，不改当前查询值。

**周/月（本期可选）**

- 默认不做；若审核要求对齐，可再加「周起始日」或「YYYY-MM」文本+对应 picker

## 5. 技术方案

### 5.1 推荐实现路径（推荐）

**在现有主进程草稿 + 打断窗预填 + sessionStore 更新 API 上增量改造**，不改存储根目录、不拆字段。

| 优点 | 风险 |
|------|------|
| 改动面小，与现有 `inputContent` / 周文件一致 | 主进程需持有草稿状态 |
| 结束链路改动集中 | 打断窗与主窗需 IPC 同步 |

备选（不推荐本期）：独立「事项」实体表 / SQLite——成本高，收益与当前规模不匹配。

### 5.2 数据与状态

**进行中（内存，主进程）**

```js
// 示意
let currentFocusMatter = ''; // 与 focusStartTime 同生命周期
```

**持久化记录（不变核心字段）**

```js
{
  id: 'focus-...',
  startTime: number,
  endTime: number,
  durationMinutes: number,
  inputContent: string  // 可被历史编辑更新
}
```

### 5.3 IPC 设计（建议）

| Channel | 方向 | 说明 |
|---------|------|------|
| `get-current-focus-matter` | R→M→R | 打开弹层时拉取草稿 |
| `set-current-focus-matter` | R→M | 保存草稿 |
| `focus-matter-updated` | M→R（可选） | 多窗口同步 |
| `interrupt-mode` 扩展 | M→R | 附带 `draft` / `inputContent` 预填 |
| `update-focus-session` | R→M→R | `{ id, inputContent }` → 成功后刷新列表 |

### 5.4 涉及改动文件（预估）

| 文件 | 改动 |
|------|------|
| `src/renderer/index.html` | 事项按钮、事项弹层；日期文本框 |
| `src/renderer/styles/main.css` | 右侧按钮、弹层、记录编辑样式 |
| `src/renderer/scripts/main.js` | 弹层逻辑、日期联动、历史编辑 |
| `src/renderer/interrupt.html` (+ 其脚本) | 预填草稿 |
| `src/main/main.js` | 草稿生命周期、IPC、结束保存合并逻辑 |
| `src/main/sessionStore.js` | `updateFocusSession` |

## 6. 交互与边界规则

1. **未开始专注**：不显示事项按钮
2. **暂停中**：仍可编辑事项
3. **专注结束瞬间**：草稿已写入或预填到打断窗，用户可再改
4. **历史编辑**：只改文案，不改变统计分钟数与次数
5. **并发**：同时只开一个事项编辑弹层；历史编辑与进行中编辑互不影响
6. **XSS**：列表继续 `escapeHtml` 展示；编辑态用 value 绑定，不走 innerHTML 注入
